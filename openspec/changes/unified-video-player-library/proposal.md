## 为什么

Flutter 在 Android、iOS、Windows、macOS 四端做影视播放时，通常需要在多个播放器内核和 UI 方案之间取舍：不同内核的 API、平台覆盖、渲染路径、字幕/音轨能力、依赖体积和异常行为都不一致。这个变更要建立一个对外统一的聚合影视播放器库，把多个播放内核封装到同一套稳定 Dart API 后面，并提供一套参考 GSYVideoPlayer 交互习惯的完整播放器 UI。

## 变更内容

- 新增统一播放器门面，用于创建、配置、控制和观察播放状态，业务方不需要直接依赖具体播放器内核。
- 新增可插拔播放器内核抽象，覆盖 Media Kit/libmpv、FVP/libmdk、官方 Video Player，以及 Erika/Rust Renderer。
- 新增内核选择、降级和能力报告机制，调用方可以指定偏好内核，也可以让库在 Android、iOS、Windows、macOS 上自动选择兼容实现。
- 新增可复用影视播放器 UI，包含进度、上一集、下一集、播放/暂停、全屏、切换播放内容或内核的入口、缩放模式、固定倍速档位。
- 统一错误、缓冲、音轨、字幕、生命周期和全屏状态在不同内核之间的表现。
- 新增文档和示例，演示同一套公开 API 在目标平台上的使用方式，并内置 MP4、HLS、DASH、错误地址和 GSY 风格交互验证场景。

## 能力范围

### 新增能力

- `unified-video-player`：聚合式 Flutter 影视播放器库的公开 API、播放器内核抽象、跨端内核选择、播放器状态模型和默认播放器控制 UI。

### 修改能力

- 无。

## 影响范围

- 代码影响：`lib/` 下的新 Dart 库 API，Android、iOS、Windows、macOS 的平台集成点，默认 Flutter UI 组件，示例应用和测试。
- 公开 API：新增控制器、播放源、内核注册表、播放状态、媒体元数据、缩放模式、倍速档位和事件流契约。
- 依赖影响：通过适配器接入 `media_kit`、`media_kit_video`、`fvp`、`video_player`、`erika_flutter` 及其平台包；依赖设计需要支持消费者按需启用较重的原生后端。
- 平台影响：Android 纹理/Surface 播放和权限，iOS/macOS 通过所选内核间接使用 AV/Metal/OpenGL 等渲染路径，Windows 纹理渲染，全屏/方向/窗口行为，以及原生二进制打包。
- 文档影响：README 和示例应用需要说明内核支持矩阵、降级规则、能力限制、推荐的生产配置和场景验证播放地址。
